# Agent 架构演进

每一份文档画的是**该版本当时的完整架构**：当时已经存在的入口、调用关系和保留下来的旧路径都在图里。后一版不会提前出现。v0.8.0 之前没有单独版本号，按代码里的阶段命名；从 v0.8.0 起与 CHANGELOG 一致。

| 文件 | 版本 | 这一版让 Agent 多了什么 |
| --- | --- | --- |
| [00-baseline.md](00-baseline.md) | 基线 | 还没有 Agent。服务端先检索知识库，再让模型回答 |
| [01-agent-loop.md](01-agent-loop.md) | Agent Loop | 模型自己决定要不要调用工具，并可以连续多步 |
| [02-task-runtime.md](02-task-runtime.md) | Task Runtime | 一次执行变成可查询的任务，有明确状态 |
| [03-v0.8.0.md](03-v0.8.0.md) | v0.8.0 MCP + Skills | 事件流式推出；本地工具和 MCP 统一解析；技能写入系统提示 |
| [04-v0.9.0.md](04-v0.9.0.md) | v0.9.0 Coding Agent | 可以改文件、跑受控命令，但必须先等人批准 |
| [05-v1.0.0.md](05-v1.0.0.md) | v1.0.0 Trace | 任务结束后仍能回看步骤、耗时和评估结果 |
| [06-v1.1.0.md](06-v1.1.0.md) | v1.1.0 Workflow | 一个任务可以按校验过的有向无环图执行节点 |
| [07-v1.2.0.md](07-v1.2.0.md) | v1.2.0 Git MCP | 通过只读 Git 工具查看仓库，不能提交或推送 |
| [08-v1.3.0.md](08-v1.3.0.md) | v1.3.0 Git 写入 | 可以暂存指定文件并提交，但必须先校验再等人批准 |
| [09-v1.4.0.md](09-v1.4.0.md) | v1.4.0 GitHub MCP | 查看配置好的仓库、Issue 和 Pull Request，不能改远端 |
| [10-v1.5.0.md](10-v1.5.0.md) | v1.5.0 Git Push | 可以把本地分支推到 origin，但必须先校验再等人批准 |
| [11-v1.6.0.md](11-v1.6.0.md) | v1.6.0 Task Persistence | 任务状态经 TaskStore 读写；当前仍是进程内内存 |
| [12-v1.7.0.md](12-v1.7.0.md) | v1.7.0 SQLite | 可选把任务写入 SQLite；重启后未完成任务收成 failed，不续跑 |
| [13-v1.8.0.md](13-v1.8.0.md) | v1.8.0 审批持久化 | 未决审批可跨重启保留；批准后只补执行那一个工具 |
